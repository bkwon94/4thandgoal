# Runbook: the site host on Cloudflare Workers

This runbook tells you how to deploy, check, and move the site of each client. Each client serves at `<slug>.4thandgoal.app`.

## What runs where

- Each client is one Cloudflare Worker with static assets. The Worker name is the client slug, such as `cpc`.
- The Worker serves the static export `apps/site/out/` of a build with `CLIENT=<slug>`. It runs no Worker script.
- An unknown path answers `404` with the `404.html` of the export, because the config sets `not_found_handling = "404-page"`.
- The site has no base path. Each link starts at `/`.
- The Custom Domain of each Worker is `<slug>.4thandgoal.app`. Brian adds it in the dashboard. The config declares no route.
- The old host `cpcfantasy.com` answers with a Redirect Rule to `cpc.4thandgoal.app`.
- The API serves at `api.4thandgoal.app`. `api.cpcfantasy.com` keeps its cert, so an old page still works.
  See `apps/pipeline/docs/runbook-site-api.md`.

## The wrangler config

The prebuild step `scripts/client-build.mjs` writes `apps/site/wrangler.jsonc` for `CLIENT`. Git ignores the file.
Do not edit it. For `CLIENT=cpc` it holds:

```jsonc
// GENERATED by apps/site/scripts/client-build.mjs from clients/cpc/client.toml. Do not edit.
{
  "name": "cpc",
  "compatibility_date": "2026-11-01",
  "assets": {
    "directory": "./out",
    "not_found_handling": "404-page"
  }
}
```

## The deploy job

- The workflow is `.github/workflows/deploy-sites.yml`.
- A push to `main` runs the workflow `Check` once. Its `workflow_run` event starts the deploy, and only a green check
  of a push deploys.
- The deploy builds the commit that the check saw, `github.event.workflow_run.head_sha`.
- The job `clients` lists each folder under `clients/` with a `client.toml`. The job `deploy` runs once per slug.
- Each deploy job builds with `CLIENT=<slug>`, runs `check:export`, and runs `wrangler deploy` with
  `cloudflare/wrangler-action@v4`.
- The job reads the repository secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`.
- A second client adds no workflow code. Its folder under `clients/` adds one deploy job.

To deploy a branch before its merge, such as the spec branch `clients`, run this command. A dispatch runs the check on
the ref first, and deploys only when the check passes.

```sh
gh workflow run deploy-sites.yml --repo bkwon94/4thandgoal --ref clients -f ref=clients
```

GitHub runs a manual dispatch only for a workflow that it knows. Before the first merge of `deploy-sites.yml` into
`main`, the command can answer `HTTP 404` or `could not find any workflows`. If it does, deploy from a clone with
the steps in "Deploy by hand".

## The dry run

A dry run needs no token. It reads the export and stops before the upload. Run it in `apps/site`:

```sh
CLIENT=cpc pnpm build
pnpm dlx wrangler@4.157.0 deploy --dry-run
```

The output on 2026-11-04:


## Deploy by hand

Use this when the job fails for a Cloudflare or GitHub reason. Run it in `apps/site` from a clean checkout.

1. Build the export of the client.

   ```sh
   CLIENT=cpc pnpm build && CLIENT=cpc pnpm check:export
   ```

2. Deploy it. Type one space before the line, so the shell keeps the token out of history.

   ```sh
    CLOUDFLARE_API_TOKEN=<the token> CLOUDFLARE_ACCOUNT_ID=<the account id> pnpm dlx wrangler@4.157.0 deploy
   ```

## The dashboard steps

Brian does each step. The steps are the manual steps 1 to 4 of `.scratch/clients/PRD.md`.

1. Add the zone `4thandgoal.app` to Cloudflare. Check: the zone shows "Active" on the Overview page.
2. Make an API token with the template "Edit Cloudflare Workers". Add the secrets to the repo:

   ```sh
   gh secret set CLOUDFLARE_API_TOKEN --repo bkwon94/4thandgoal
   gh secret set CLOUDFLARE_ACCOUNT_ID --repo bkwon94/4thandgoal
   ```

   Check: `gh secret list --repo bkwon94/4thandgoal` lists both names.
3. Run the deploy job once, so the Worker exists. Then open Workers & Pages, the Worker `cpc`, Settings, Domains &
   Routes, and add the Custom Domain `cpc.4thandgoal.app`. Check: `curl -sI https://cpc.4thandgoal.app/` answers `200`.
4. Add the Redirect Rule on the zone `cpcfantasy.com`. See the next section.

## The Redirect Rule of cpcfantasy.com

A Redirect Rule acts only on proxied traffic. Before you add the rule, set the DNS records `cpcfantasy.com` and
`www.cpcfantasy.com` to "Proxied". If a record stays "DNS only", the request goes to GitHub Pages and the rule does
nothing.

Open the zone `cpcfantasy.com`, then Rules, then Redirect Rules, then "Create rule".

### The narrow first form

Add this form first. It sends only the week 8 pages, so a mistake breaks one week and not the whole site.

| Field | Value |
| --- | --- |
| Rule name | `cpc week 8 to 4thandgoal` |
| If incoming requests match | Custom filter expression |
| Expression | `(http.host in {"cpcfantasy.com" "www.cpcfantasy.com"} and starts_with(http.request.uri.path, "/2026/week-08/"))` |
| Then, Type | Dynamic |
| Expression | `concat("https://cpc.4thandgoal.app", http.request.uri.path)` |
| Status code | `301` |
| Preserve query string | On |

While the narrow form is live, the other paths still go to GitHub Pages through the proxy. Set SSL/TLS to "Full"
on the zone. "Flexible" makes a redirect loop with GitHub Pages.

Check:

```sh
curl -sI https://cpcfantasy.com/2026/week-08/ | grep -iE '^(HTTP|location)'
```

Expect `HTTP/2 301` and `location: https://cpc.4thandgoal.app/2026/week-08/`.

### The full form

When the narrow form passes its check, change the expression of the match. Keep each other field.

| Field | Value |
| --- | --- |
| Rule name | `cpc to 4thandgoal` |
| Expression | `(http.host eq "cpcfantasy.com") or (http.host eq "www.cpcfantasy.com")` |
| Then, Type | Dynamic |
| Expression | `concat("https://cpc.4thandgoal.app", http.request.uri.path)` |
| Status code | `301` |
| Preserve query string | On |

Check:

```sh
curl -sI https://cpcfantasy.com/ | grep -iE '^(HTTP|location)'
curl -sI 'https://www.cpcfantasy.com/rankings/?a=1' | grep -iE '^(HTTP|location)'
```

Expect `301` and `location: https://cpc.4thandgoal.app/`, then `location: https://cpc.4thandgoal.app/rankings/?a=1`.

A browser keeps a 301 in its cache. Test a change to the rule with `curl`, not with a browser.

## After the move

The repo has no GitHub Pages deploy. The last Pages deploy can still answer at `bkwon94.github.io`.
Brian can turn off Pages in Settings, then Pages, of the repo, after the full form passes its check.
